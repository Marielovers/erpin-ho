# 그저 30초 동안 에르핀을 쓰다듬기만 하면 되는 게임

Live2D 웹 상호작용 게임. Vite + npm + `live2d-web`(로컬 패키지). 게임 중 별도의 LV·리셋 버튼은 표시하지 않습니다. 제목/시작 버튼은 시작 화면에서만 표시됩니다.

## Windows CMD에서 실행

```cmd
npm install
npm run dev
```

`http://localhost:5173` 접속. 최초 실행 시 `scripts/setup-core.mjs`가 Live2D 공식 서버에서 Cubism Core를 내려받아 `public/vendor/`에 저장합니다. **브라우저의 실행 시점에는 CDN에 연결하지 않습니다.** Core 파일은 라이선스상 저장소에 포함하지 않았습니다.

## GitHub에 CMD로 업로드

1. GitHub에서 새 빈 저장소를 만듭니다. (README 초기화 선택 해제 권장.)
2. 프로젝트 폴더에서 CMD를 열고 다음을 실행합니다. `git-upload.cmd`를 실행하면 저장소 URL을 입력하도록 안내합니다.

또는 CMD 명령어를 직접 입력합니다.

```cmd
git init
git branch -M main
git add .
git commit -m "Live2D web game"
git remote add origin https://github.com/USERNAME/REPOSITORY.git
git push -u origin main
```

이미 연결한 저장소를 업데이트할 때:

```cmd
git add .
git commit -m "Update Live2D game"
git push
```

**GitHub Pages 배포:** 저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 지정합니다. `.github/workflows/deploy.yml`이 `main` 브랜치 push 때 자동 빌드·배포합니다. 배포 URL은 보통 `https://USERNAME.github.io/REPOSITORY/`입니다. Vite `base: './'`를 사용해 프로젝트 경로도 지원합니다.

자동 배포에는 서버가 Cubism Core를 다운로드할 수 있어야 합니다. 배포 전에 Live2D SDK 사용·배포 라이선스를 확인하세요: https://www.live2d.com/ko/sdk/license/ (일부 이용 형태에는 계약이 필요할 수 있습니다).

## 작업 파일/주의사항

- `public/assets/background.png`: 첨부된 배경 이미지
- `public/voices/Voice_Erpin_Touch2_Skin3.wav`: 머리 쓰다듬기 종료 시 재생(볼륨 50%)
- `public/model/`: **이전 버전의 모델이 들어 있습니다.** 최신 수정한 모델(`ojum` 포함)을 여기로 복사해야 외형과 새 파라미터가 동작합니다. `model3.json` 파일명과 모션/Hit Area 등록도 유지하세요.
- `src/main.js`의 `modelFit()`에서 모델 크기(PC 1.08 / 모바일 1.22) 조정 가능
- `src/game-rules.js`: bellyhit 1회 → `dust=1`, 5회 → `ojum=1`. LV와 기존 표정/색상 효과는 내부 저장 유지
- 머리 touch: `headX`/`headY` 동시 드래그. 다른 상호작용을 한 번이라도 하면 이후 머리 쓰다듬기 자체가 영구적으로 잠기고 행복 엔딩도 불가능합니다.
- 게임 중에는 상태값·리셋 UI가 없지만 저장된 기록은 유지됩니다. 개발 중 리셋하려면 브라우저 개발자 도구(F12) 콘솔에서 `localStorage.removeItem('erpin-live2d-interactive-v1'); location.reload()` 실행

## 30초 머리 쓰다듬기 행복 엔딩 (최신)

- 머리를 움직이며 쓰다듬은 시간만 누적해 **총 30초**가 되면 반투명 흰색 화면에 `에르핀은 영원히 행복할 겁니다`를 표시합니다. 가만히 누른 시간은 계산하지 않습니다.
- 엔딩에서 `public/voices/Voice_Erpin_Joy3.wav`를 50% 볼륨으로 재생합니다. 재생 중인 다른 대사는 끊고 엔딩 음성만 재생해 서로 겹치지 않습니다.
- `eyeopen=0`, `smile=0`을 모션 갱신 단계에서 계속 고정합니다. 엔딩은 새로고침해도 유지되지만 음성은 자동 재생하지 않습니다.
- **중요한 기믹:** 모션을 발생시키는 타격, `breasttouch`, `skirtopen` 드래그를 단 한 번이라도 하면 엔딩을 볼 수 없습니다. LV 상승을 일으키지 않는 치마 드래그라도 엔딩을 잠급니다. 이전 게임 기록에 LV나 타격 이력이 있는 경우에도 동일합니다.
- 엔딩 이후에는 머리 쓰다듬기만 가능하고 나머지 Hit Area는 무시합니다.
- 머리의 `headX/headY`, 가슴의 `boobX1/boobY1`은 손을 떼면 수동 고정을 해제하고 실제 물리 연산 출력값으로 부드럽게 보정해 돌아가게 합니다. 안정화 시 스프링도 해제하므로 물리 연산이 계속 작동합니다.
- 기존 LV 표정 변화, 효과음, 음성 0.5초 지연, 누적 타격 색상과 `dust/ojum` 조건은 그대로입니다.
- 게임 내 LV 표시나 초기화 버튼은 없습니다. 처음부터 엔딩을 다시 시험하려면 F12 콘솔에 아래 코드를 붙여넣고 새로고침하세요.

```js
localStorage.removeItem('erpin-live2d-interactive-v1'); location.reload();
```

## 대사 겹침 방지 — 대기열 제거 (최신)

- 타격 효과음(`public/sfx/`)은 **기존대로 동시에 여러 개 재생 가능**합니다.
- `Hit / Sorrow` 음성은 타격음 실행 0.5초 후 시작되지만, **그 0.5초 대기 중에도 음성 채널을 점유**합니다.
- 머리 쓰다듬기 음성도 동일한 채널을 사용합니다.
- 음성이 재생 중이거나 시작 대기 중이면 새 음성 요청은 **바로 무시**합니다. 기다렸다가 나중에 재생하는 대기열은 없습니다.
- 30초 행복 엔딩이 발생하면 진행 중인 음성이나 예약을 즉시 중단하고 `Voice_Erpin_Joy3.wav`만 재생합니다. 이후에는 다른 음성을 영구적으로 재생하지 않습니다. 엔딩 상태를 복원한 경우 새 음성은 조용히 차단합니다.
- 음성 볼륨은 50%입니다.

## 머리 쓰다듬기 모션 (최신)

- `touch` Hit Area를 클릭만 하면 모션이 시작되지 않고 **실제로 드래그가 시작될 때** `touch.motion3.json`을 `model.playMotion('touch', 0, ...)`로 한 번 재생합니다.
- 드래그 중에는 `eyeopen=0`, `smile=0`을 모션/물리 뒤에 매 프레임 적용해 확실히 눈을 감도록 합니다.
- 손을 떼면 모델 기본 표정으로 복귀합니다. 기존 `touch.motion3.json`이 `Loop: true`인 경우에도 표정이 계속 감긴 채 남지 않도록 드라이버를 유지합니다. 다음 타격 모션이 발생하면 그 드라이버는 완전히 해제되고 타격 모션이 우선됩니다.
- 머리의 `headX`/`headY` 드래그와 스프링·물리 연산 복귀는 유지됩니다.
- 엔딩 중에는 `eyeopen=0`, `smile=0`이 영구 고정됩니다. 엔딩 이후 머리 쓰다듬기를 계속해도 일반 음성은 재생하지 않습니다.

## 2026-11-08 기능 동작 수정 (LV / 드래그 / 숨겨진 엔딩)

이전 버전에서는 LV 규칙의 값이 JS 상태로는 계산되어도 프레임 업데이트 동안 모션·물리 영향과 충돌할 수 있었고, 드래그 복귀는 물리 **출력** 파라미터를 모델 기본값으로만 되돌리려 해서 화면에서 곧바로 튀거나 제대로 복귀하지 않는 문제가 있었습니다.

- **LV 1 이상:** `eyelight=1`을 매 프레임 **모션/물리 뒤**에 재적용합니다.
- **LV 20 이상:** `pupil=1`도 같은 방식으로 유지합니다. 기존 LV 표정 단계, `dust`, `ojum`, 눈물, 혈흔, 색상·음성 규칙은 유지합니다.
- **머리:** `headX` + `headY` 드래그를 놓으면 실제 물리 계산값을 목표로 감쇠 복귀합니다.
- **가슴:** `boobX1` + `boobY1`도 동일합니다. 물리 엔진은 계속 갱신되며, 복귀 중 화면값만 스프링으로 보정합니다. 충분히 수렴하면 보정 드라이버를 제거합니다.
- **치마:** 물리 출력값이 아니므로 모델의 기본값까지 천천히 감쇠 복귀합니다.
- **엔딩:** 머리 외 영역의 첫 접촉/타격/드래그가 한 번이라도 발생하면 머리 쓰다듬기 자체와 행복 엔딩이 모두 영구적으로 잠깁니다. LV 등 다른 규칙은 계속 작동합니다.
- **엔딩 성공:** 다른 상호작용 없이 머리 쓰다듬기 누적 30초를 달성하면 기존 흰색 엔딩 화면 및 음성이 재생되며, 이후에는 머리만 조작할 수 있습니다.

화면 UI는 바뀌지 않습니다. 브라우저 F12 콘솔에서 `__erpinDebug()`를 실행하면 현재 LV, 실제 `eyelight`/`pupil` 값, 엔딩 불가 상태, 복귀 중인 파라미터를 확인할 수 있습니다. 게임 저장 기록이 남아 있으면 이전 LV·엔딩 불가 상태도 이어지므로, 처음부터 시험하려면 아래 저장소 삭제 명령을 사용하세요.

**테스트 범위:** Live2D 모델링을 사용하지 않는 코드 기반 단위·모의 프레임 테스트가 통과했습니다. 수정한 최신 `.moc3` 및 실제 Cubism Core의 렌더링 결과는 여기서 재현하지 못했습니다. `public/model`은 과거 버전이므로 반드시 사용 중인 최신 모델 폴더를 보존·적용하세요.

- 게임 제목은 **그저 30초 동안 에르핀을 쓰다듬기만 하면 되는 게임**입니다.

## LV 눈 파라미터 확인(2026-11-08)

`eyelight`는 LV 1 이상, `pupil`은 LV 20 이상에서 `live2d-web`의 지속 파라미터 고정 API(`setParameter`)로 매 프레임 모션 및 물리 계산 이후 1이 적용됩니다.

F12 → Console → `__erpinCheckLv()`를 실행하면 실제 로딩된 모델의 파라미터 ID, 범위, 기대값, 현재값, 고정 등록 여부와 코드 버전을 검사합니다. `actual=1`인데도 변화가 보이지 않는다면 최신 `.moc3`의 디포머·아트메쉬 연결 및 키폼을 확인해야 합니다. `registered=false`라면 새 모델의 파라미터 ID 또는 모델 경로가 다른 것입니다. `lv=0`이면 먼저 LV를 올려야 합니다.

**주의**: 번들 전체 프로젝트의 모델은 이전 버전입니다. 모델을 최근 수정했다면 코드 패치만 적용하거나 `public/model/`의 최신 모델을 유지하세요. 새 빌드가 안 보이면 강력 새로고침(`Ctrl+Shift+R`) 또는 GitHub Pages 최신 Actions 배포 여부도 확인하세요.

## LV 10~20 eyeopen 기본값 단계 변화 (이번 수정)

- LV 0~9: 기본 모델값(보통 1), 자동 제어하지 않음.
- LV 10: `eyeopen=1.00`, LV가 한 단계 오를 때마다 0.05씩 감소 (`LV15=0.75`), LV 20 이상에서는 `eyeopen=0.50` 유지.
- 값은 모션/물리 계산 이후 지속 적용. 기존 LV 1 이상 `eyelight=1`, LV 20 이상 `pupil=1` 유지.
- 다른 상호작용을 하면 쓰다듬기가 잠기므로 LV 10 이상 상태와 정상적인 머리 쓰다듬기는 동시에 발생하지 않습니다. 머리만 쓰다듬는 중에는 기존처럼 `eyeopen=0`, 행복 엔딩 이후에도 `eyeopen=0`이 유지됩니다.
- F12 콘솔에서 `__erpinDebug()`를 실행하면 `eyeopen`, `expectedEyeopen`도 확인 가능합니다.
- 수정된 모델은 포함되지 않았습니다. 모델/음원/배경을 유지하려면 패치 ZIP에서 `src/main.js`, `src/game-rules.js`만 덮어쓰세요.
